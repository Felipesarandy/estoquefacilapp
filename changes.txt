EstoqueFacil - o que mudou (avisos para o grupo)
Atualizado em 18/11/2026 (versao final)

1. Backend unificado em backend/. A API da pasta estoquefacil-feature-backend
   esta sendo portada para la, adaptada ao haras. A pasta do feature serve so
   de referencia e sai do projeto no final.

2. Dominio: HARAS (Stable, papeis admin e tratador). O modelo de "loja"
   (Store, funcionario) NAO sera usado.

3. models.py virou um pacote: backend/app/models/ (um arquivo por tabela).
   Os imports continuam iguais:
   from app.models import Product

4. API REST em /api (ex.: /api/products). Erros sempre em JSON:
   {"error": {"status": 404, "message": "..."}}

5. Nao existe cadastro publico (/register). O primeiro admin vem do seed
   (flask seed) e os demais usuarios sao criados por um admin.

6. "Quebra de estoque" = colchao minimo (min_stock): o estoque de seguranca
   para o produto nao acabar. O sistema alerta ate 5 dias antes da quebra
   (cobertura <= 5 dias). A constante MOTIVOS_QUEBRA foi renomeada para
   MOTIVOS_PERDA (avaria, vencimento, furto continuam como motivos de saida).

7. Migrations: d2b9e292d1e5 (modelo inicial) -> 84631ed584e8 (auditoria e
   incidentes). Mudancas no banco entram em novas migrations por cima, e so
   UMA pessoa gera migrations. Avisem antes de mexer nos models.

8. Banco local pode ser recriado a qualquer hora (dados sao ficticios):
   apagar backend/instance/dev.db, flask db upgrade, flask seed.

9. Arquivos do backend agora usam fim de linha LF (antes CRLF).

10. Front-end fica na pasta frontend/ (Vue 3 + Vite + Tailwind), pronto: 11 telas
    (Painel, Produtos, Categorias, Fornecedores, Alertas, Movimentacoes,
    Registro diario, Inventario, Incidentes, Auditoria e Usuarios) mais o login.

11. Nunca versionar: .env, *.db, .venv/. Use backend/.env.example como base.

12. Movimentacoes de estoque (POST/GET /api/movements): sao IMUTAVEIS (sem
    editar nem apagar). Correcao = nova movimentacao com motivo "ajuste" e
    observacao. Saida acima do saldo retorna 409. Registro diario em
    GET /api/movements/daily (por dia, por produto e por usuario).

13. Alertas de quebra de estoque: GET /api/alerts e GET /api/dashboard.
    Niveis: ruptura, critico, atencao, ok. ALERTA_DIAS_ANTECEDENCIA=5 (.env).

14. Logging configurado (LOG_LEVEL no .env, padrao INFO). `flask seed` agora
    gera dados de demonstracao com os 4 niveis e 7 dias de historico.

15. A pasta estoquefacil-feature-backend foi removida do projeto (ha backup
    em D:\Code\backup_pre_integracao). O codigo util ja esta em backend/.

16. Confirmar com o professor: so o modelo de auditoria ITIL. O formato do
    registro diario de entradas/saidas e a regra dos 5 dias sao decisao do grupo.

17. Revisao antes da apresentacao (18/11/2026):
    - Horarios (created_at, closed_at...) agora saem no fuso do haras com
      offset, ex.: "2026-11-17T23:03:56-03:00". Antes saiam em UTC sem fuso
      e o front mostraria a hora 3h adiantada. O banco continua em UTC.
    - Erros 404/405 padrao do Flask agora vem em portugues.
    - Seed: "Racao de potros" passou a consumir 9 kg/dia (antes 30). Assim o
      insumo em "atencao" dura mais (~4,4 dias) que os "critico" e a ordem
      dos alertas faz sentido na apresentacao.
    - .env.example da raiz agora e igual ao backend/.env.example (tinha
      ficado sem JWT_SECRET_KEY e gerava aviso de chave curta no login).
    - Ambiente virtual padronizado como .venv (README da raiz atualizado).
    - +4 testes (306 no total).

18. Exclusao de categorias (DELETE /api/categories/<id>), somente pelo admin.
    - Regra: se a categoria tiver produtos vinculados (ativos ou inativos),
      a API recusa com erro 409 e a tela mostra o motivo; se estiver vazia,
      e excluida de verdade (204).
    - A exclusao e registrada na auditoria (acao "delete", com os dados
      da categoria antes de apagar).
    - As demais entidades (produtos, usuarios, fornecedores, movimentacoes)
      continuam sem DELETE; produtos e usuarios seguem com desativacao
      (PATCH active=false).
    - No frontend, o botao Excluir aparece apenas para o admin.
    - Nao ha migracao nova: quem tem o banco local antigo so precisa rodar
      `flask seed --force` (opcional, para recriar os dados de demonstracao).

19. Front-end (frontend/): como rodar e o que saber.
    - Dois terminais: backend (flask run, porta 5000) e frontend (npm run dev,
      porta 5173). Copie frontend/.env.example para frontend/.env.
    - A API nao tem versao na URL: tudo em /api (ex.: /api/products).
    - Na interface o termo e "Produto" (a API e a documentacao antiga ainda
      dizem "insumo" em algumas mensagens de erro).
    - Algumas listas aplicam filtros no navegador porque a API nao os oferece:
      nivel em Produtos, gravidade/periodo/"nao fechados" em Incidentes,
      divergencia em Inventario e busca por texto em Usuarios. Nesses casos a
      tela busca todas as paginas e pagina localmente.
    - Token JWT fica no localStorage (chave estoquefacil_token). Se expirar,
      aparece o aviso "Sua sessao expirou" e volta para o login.
    - A pagina /_ui (catalogo de componentes) so existe em npm run dev.
    - Resultado final dos testes do backend: 313 testes, 37 rotas.
